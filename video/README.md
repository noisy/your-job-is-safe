# Your Job Is Safe! — music video

A music video for the satirical pop-punk song in `audio/song.mp3` (3:24), with every pixel generated by
code: three.js / WebGL, shaders and Canvas2D, rendered frame by frame in headless Chrome and muxed with
FFmpeg. Every frame is a deterministic function of song time, so the browser preview and the offline
1080p60 export are identical. The story and every reference are in `../handoff.md`; the brief is `../prompt.md`.

## Layout

- `audio/song.mp3` — the song (copy of `../Your job is safe.mp3`).
- `lyrics/lyrics.src.txt` — the lyrics as sung, by section (the aligner's input).
- `analysis/` — Python (uv, Python 3.11) tools that produce the timing data the renderer reads:
  - `ctc_emissions.py` — CTC emissions of the Demucs vocal stem from two acoustic models (MMS_FA and wav2vec2 LV60K).
  - `whisper_run.py` — Whisper large-v3-turbo word timestamps (mlx-whisper), the independent cross-check.
  - `align.py` → `data/lyrics.json` — one global star-token CTC Viterbi pass over the whole song (fused models), word ends extended through held notes, low-confidence words refined against Whisper; report in `analysis/qa/align_report.txt`.
  - `analyze.py` → `data/audio.json` — beats/downbeats (beat_this), a repaired grid (half-time bridge filled, 20 ms quantisation smoothed, no fake beats in the unaccompanied intro), kick/snare/hat hits from the drum stem, loudness envelopes per stem and per band, sections, `musicStart`, `splice` (3:12.45).
  - `qa_plot.py <from> <to>` — waveform + spectrogram with words, beats and hits, for spot checks.
- `data/lyrics.json`, `data/audio.json` — the timing data (committed; everything the renderer needs).
- `app/` — the renderer: TypeScript + three.js, bun + Vite. The engine (`src/engine/`) is forked from
  [pdoom-video](https://github.com/mexicat/pdoom-video) by Giacomo Magnanini (mexicat), MIT: see
  `LICENSE-pdoom-video-engine`.
  - `src/ps1/` — the PS1 kit every scene is built on: `stage.ts` (the `Ps1Stage` base class: 384×216 world,
    vertex snapping, 15-bit dither; panels hung in the world, typed dialogue, block titles, labels),
    `cast.ts` (DEV, the chatbot head and body, DEV's room), `gfx.ts` (bitmap font, PS1 material), `palette.ts`.
  - `src/scenes/` — one module per scene of the edit (some serve several entries through params);
    `style-*.ts` are the ten Phase-1 style explorations (`style-ps1.ts` is the chosen one).
  - `src/timeline.ts` — the edit: scene windows anchored to lyric lines and cut on downbeats.
- `docs/` — `TREATMENT.md` (the treatment, style bible and scene-by-scene plan), `STORY.md` (the story
  beats), `ENGINE.md` (scene API), `PHASE1-BRIEF.md` (the style exploration brief).

## Requirements

[bun](https://bun.sh), Google Chrome (driven headless through playwright-core), ffmpeg with libx264, and
[uv](https://docs.astral.sh/uv/) for the analysis only.

## Regenerate the timing data

```sh
cd analysis
uv venv --python 3.11 .venv && uv pip install --python .venv/bin/python -r pyproject.toml
ffmpeg -i ../audio/song.mp3 -c:a pcm_f32le -ar 44100 work/mix.wav        # gapless decode = the time reference
.venv/bin/python -m demucs -n htdemucs_ft -o stems --float32 work/mix.wav   # stems/htdemucs_ft/mix/*.wav
.venv/bin/python ctc_emissions.py && .venv/bin/python whisper_run.py turbo
.venv/bin/python align.py          # data/lyrics.json   (--models mms,lv60k by default)
.venv/bin/python analyze.py        # data/audio.json
```

Models download ~4 GB into `analysis/.cache/` (delete it afterwards). If a private package index is
configured globally for uv/pip, prefix the install with `UV_NO_CONFIG=1 PIP_CONFIG_FILE=/dev/null` and pass
`--index-url https://pypi.org/simple`.

## Preview

```sh
cd app
bun install
bunx vite --port 5420          # http://localhost:5420  the whole video (?t=42 starts there, ?style=<id> previews a Phase-1 style)
bun run storybook              # Phase 1: http://localhost:6006, one story per style with audio + scrub
```

Keys: space play/pause, ←/→ ±1 s (shift ±5 s), `,`/`.` ±1 frame, `[`/`]` previous/next scene.

## Render

The renderer uses the dev server at `--url` (default http://localhost:5420, or `$YJIS_URL`).

```sh
cd app
bun scripts/render.ts stills --t 42.9,45.7 [--style <id> | --only <ids>] --out ../../out/wip/x
bun scripts/render.ts sheet --from 40 --to 48 --n 24 --cols 6 [--style <id>] --out ../../out/wip/sheet.png
bun scripts/render.ts perf --from 42 --to 47 [--style <id>]
bun scripts/render.ts video --from 40 --to 48 [--style <id>] --samples auto --shutter 0.2 --out ../../out/clip.mp4
bun scripts/styles.ts          # Phase 1 deliverables: out/styles/NN-<id>.png/.mp4 + contact-sheet.png
bun scripts/qa.ts              # out/qa/: contact sheets of the whole song, frames around every cut, lyric-sync checks
bun scripts/final.ts           # out/your-job-is-safe.mp4 (1080p60, motion blur) + out/your-job-is-safe-web.mp4 (~16 Mbit/s)
```

Every mode takes `--skin paper` for the paper-craft version of the same edit (`final.ts --skin paper` →
`out/your-job-is-safe-paper.mp4` and `-paper-web.mp4`; preview: `?skin=paper`).

`final.ts` renders the song as `--jobs` parallel segments (frame-exact boundaries, default 2), concatenates
them without re-encoding, muxes the mp3 (AAC 320k) and encodes the web copy. Motion blur: `--samples auto`
(adaptive, up to `--max-samples 36`) over a `--shutter 0.2` of the frame time.
